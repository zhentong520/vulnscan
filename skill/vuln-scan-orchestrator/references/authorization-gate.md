# DAST 授权闸门（与 pentest-orchestrator 同源）

## 为什么需要

静态扫描（SAST/SCA/Secrets/IaC）针对**文件**，读的是自己的代码，风险仅在于隐私。
动态扫描（DAST：ZAP / Nuclei）会**主动向运行中的系统发请求**——哪怕只是探测，
对不属于你的系统也可能构成《网络安全法》第 285/286 条意义上的非法侵入/破坏。
所以 DAST 一律先过闸门，**缺任一要素直接终止，不降级为"先扫扫看"**。

## 授权四要素（逐项打勾，全部满足才放行）

```
[ ] 1. 授权主体：目标资产的所有者本人，或持有其签字的书面授权
        （口头同意 / 群聊截图不算；"是我们公司的"但拿不出书面材料不算）
[ ] 2. 目标范围：明确到 URL / IP / 端口列表，不含模糊表述（"以及相关系统"不算）
[ ] 3. 时间窗：明确的起止时间，扫描不得超出
[ ] 4. 方法边界：允许的测试强度（passive / active / 破坏性操作是否允许）
```

## 放行后的执行约束

- 先 **passive-only**（zap-baseline.py），人工复核基线结果后再决定是否 active
- active 扫描前**再次向用户确认**目标与时间窗（自助系统也一样，防止打错环境）
- 扫描速率限制（ZAP `-z "-config connection.timeoutInSecs=30"` 等参数控制）
- 生产环境默认拒绝 active，建议在预发环境做

## 记录要求

报告里附授权摘要：授权方、日期、范围、时间窗、方法边界。没有这些信息 = 没过闸门 = 不该有 DAST 结果。
